# Лория — веб-RPG с суверенным ИИ-мастером

Текстовая ролевая игра в духе [@Loria_AI_bot](https://t.me/Loria_AI_bot), но как самостоятельное приложение:
мастер не поддакивает, кубик кидает сервер, а аудитор состояния не даёт нарисовать себе 500 золота.

![Миры Лории](public/art/world-ash.jpg)

## Что внутри

- **Два интерфейса, один движок** — браузерное приложение и Telegram-бот (`npm run bot`) с теми же правилами,
  памятью и валидатором.
- **Шесть готовых миров** — тёмное фэнтези «Пепел Вельдгарда», киберпанк «Хром и слякоть»,
  космический хоррор «Тишина „Кассандры“», нуар «Дождь над Порт-Анной», славянский фольклор
  «Лес, который слушает» и постапокалипсис «Соляная пустошь» — плюс конструктор своего мира.
- **Портреты героев** — пять архетипов с живописными портретами; внешность и имя влияют на сцену.
- **Суверенный Гейм-Мастер.** Промпт запрещает мастеру льстить, решать за игрока и отменять последствия.
  У мира есть тон, правила и собственная логика — модель обязана им следовать.
- **Серверные броски.** d20 / 2d6 / d100, сложность зависит от типа действия, а не от настроения модели.
  Модель получает готовый результат и обязана описать его, а не придумывать исход.
- **Валидатор состояния.** Любые изменения HP, энергии, золота, инвентаря, флагов и квестов проходят
  через жёсткие лимиты. Попытка выдать себе богатство срезается и попадает в журнал аудитора.
- **Гибридная память мира.** Незыблемые факты (клятвы, имена, смерти) + лексический поиск с IDF
  по прошлым сценам и свежести. Всё локально, без внешних эмбеддингов.
- **Аудитор правил.** Локальные проверки на каждом ходу (смерть без причины, экономика, агентность)
  и опциональная вторая модель для строгой проверки по кнопке.
- **Опыт и уровни.** Опыт даётся за выживание, а не за победы: успех даёт больше, критический провал — ноль.
  На новом уровне герой выбирает одно улучшение (характеристика, здоровье, энергия или запас рывков) —
  список улучшений задаёт сервер, модель к нему не допускается.
- **Рывок и передышка.** Рывок — второй серверный бросок за ход с выбором лучшего (1 раз, восстанавливается
  передышкой). Передышка меняет энергию на здоровье без запроса к модели.
- **Смерть окончательна.** На «Хардкоре» — без права на ошибку. Но можно взять «ветку» — вернуться с полпути
  в копии истории. Хронику можно забрать в Markdown.
- **Резервный рассказчик.** Если ключа нет или модель недоступна, игра не встаёт: сцены пишет
  процедурный движок с теми же правилами.
- **Отмена хода.** Два снимка состояния: можно откатить последний ход (после смерти — только «ветка»).
- **Перенос истории.** Сохранение скачивается JSON-файлом и импортируется в другой браузер или на другой сервер.
- **PWA.** Приложение ставится на телефон, оболочка кэшируется, ночная тёмная тема и клавиши 1–3 / H.

## Быстрый старт

```bash
# нужен Node.js 18+
npm start        # веб: http://localhost:3000
npm run app      # то же, но сам открывает браузер (настольный запуск)
npm run bot      # Telegram-бот, если задан TELEGRAM_BOT_TOKEN
```

Для Windows есть готовый `release/Loria.exe` — один файл без установки, см. ниже.

Telegram-бот читает токен из `.env`:

```env
TELEGRAM_BOT_TOKEN=123456:AA...
LORIA_PUBLIC_URL=https://твой-домен    # необязательно: ссылка на веб-версию
```

Бот работает через длинный polling — вебхук и домен не нужны. Он поддерживает кнопки вариантов,
свободный текст, **голосовые** (распознавание через OpenRouter STT), рывок, отмену хода,
`/hero`, `/audit`, `/export` (хроника файлом), `/new` и `/help`.

Чтобы в карточке мира показывалась обложка, задай публичный адрес — Telegram не умеет отправлять
локальные файлы:

```env
LORIA_PUBLIC_URL=https://твой-домен
```

Открой [http://localhost:3000](http://localhost:3000) и начни историю.

Ключ OpenRouter кладётся в `.env`:

```env
OPENROUTER_API_KEY=sk-or-...
LORIA_MODEL=google/gemini-2.5-flash
```

Файл `.env` уже исключён из Git. Ключ никогда не отдаётся браузеру — все запросы к модели идут с сервера.

Проверить окружение:

```bash
npm run doctor
```

Если модель молчит, доктор скажет почему:

| Ответ | Что делать |
|---|---|
| `401` | ключ отклонён — создай новый на openrouter.ai/keys |
| `402` | на ключе нет кредитов — сервер сам попробует бесплатные варианты моделей |
| «нет связи» | проверь интернет или задай прокси в `OPENROUTER_BASE_URL` |
| `404` | модель переименована — сервер возьмёт другую из каталога OpenRouter |

Дополнительно: `LORIA_MODELS` — список запасных моделей через запятую, `LORIA_AI_AUDIT=1` — строгий аудит каждым ходом.

## Проверки

```bash
npm run check    # всё сразу: юнит-тесты, тест бота и сквозной тест
npm test         # 30 юнит-проверок: кубики, лимиты, память, смерть, опыт, миграция
npm run bot:test # 11 проверок Telegram-бота без сети
npm run e2e      # 15 сквозных проверок через мок-OpenRouter: промпт → модель → валидатор → экспорт
npm run doctor   # ключ, сеть, модели, порт
```

`npm run e2e` поднимает локальную заглушку OpenRouter (`scripts/mock-ai.js`) и проверяет весь ИИ-путь
без интернета и без трат: открывающую сцену, ход с рывком, валидатор, аудит, уплотнение памяти,
отмену хода, ветку, скачивание и импорт сохранения.

## Автономный `Loria.exe` (Windows)

`release/Loria.exe` — это игра в одном файле: внутри Node.js, сервер и вся графика, ничего
устанавливать не нужно. Двойной клик — открывается браузер с игрой.

- Сохранения лежат рядом с `.exe` в папке `data/`; если папка только для чтения — в `%LOCALAPPDATA%\Loria`.
- При первом запуске рядом появляется `.env.example`: переименуй в `.env` и впиши `OPENROUTER_API_KEY`,
  чтобы сцены писал живой мастер. Без ключа работает резервный рассказчик — правила те же.
- Сервер слушает только `127.0.0.1`; порт 3000, если занят — берётся следующий свободный.
- Консольное окно — это и есть сервер: свернуть можно, закрыть — игра остановится.
- Файл не подписан, поэтому SmartScreen скажет «Windows защитила ваш компьютер»:
  «Подробнее» → «Выполнить в любом случае».
- Если в `.env` задан `TELEGRAM_BOT_TOKEN`, вместе с игрой поднимется и бот.

Собрать самому:

```bash
npm install
npm run build:exe                                  # release/Loria.exe (~100 МБ)
npm run build:exe -- --target linux                # release/loria-linux
```

Сборка идёт через Node SEA: esbuild собирает лаунчер и сервер в один CommonJS-файл,
`node --experimental-sea-config` делает blob, `postject` вшивает его в официальный `node.exe`,
`resedit` ставит иконку и свойства файла. Blob совместим только с той версией Node, которой
его собрали, поэтому рядом с `node.exe` должна быть та же версия (скрипт скачивает её сам).

## Docker

```bash
docker compose up -d --build     # веб и бот, истории в томе loria-data
```

Бот поднимется, если в `.env` есть `TELEGRAM_BOT_TOKEN`; иначе контейнер просто перезапустится,
а веб продолжит работать.

## Как это работает

```
Браузер
  │  выбор мира, лист героя, память мира
  ▼
Node-сервер (без зависимостей)
  ├─ dice.js      серверный бросок + исход (модель не может его изменить)
  ├─ prompts.js   жёсткий системный промпт: мир, герой, память, запрет поддакивать
  ├─ ai.js        OpenRouter: перебор моделей, повторы, таймауты, JSON
  ├─ state.js     валидатор: лимиты HP / энергии / золота / инвентаря / флагов
  ├─ memory.js    факты + поиск по прошлым сценам (IDF, сущности, свежесть)
  ├─ auditor.js   локальный аудит и опциональная проверка второй моделью
  └─ store.js     JSON-файлы в data/games, экспорт в Markdown
```

Ход устроен так:

1. Игрок выбирает вариант или пишет своё действие.
2. Сервер определяет характеристику и сложность, кидает кубик, фиксирует исход.
3. Модель получает мир, героя, память, результат броска и возвращает JSON: сцену, варианты,
   предложенные изменения, факты для памяти, NPC.
4. Валидатор применяет изменения в допустимых пределах и записывает каждое ограничение в журнал.
5. Факты и фрагменты сцены уходят в память. Следующий ход мастер уже помнит, о чём вы договорились.

### Что именно запрещено модели

| Соблазн | Что происходит |
|---|---|
| «У меня 500 золота» | Валидатор срезает до лимита мира за ход, попытка логируется |
| Вылечить героя «насовсем» | Максимум +4 HP за ход |
| Объявить смерть без нуля HP | Смерть отклоняется аудитором |
| Решить за игрока, что он чувствует | Локальный аудит помечает нарушение агентности |
| Выдать предмет, которого нет | Инвентарь ограничен 16 слотами, лишнее отбрасывается |
| Проигнорировать бросок | Бросок уже в промпте, исход проверяется по тексту |

## Режимы

| Режим | Как включить | Что делает |
|---|---|---|
| ИИ-мастер | ключ в `.env` | Полноценные сцены через OpenRouter |
| Резервный | ключа нет или модель упала | Процедурные сцены, игра продолжается |
| Принудительный резерв | `LORIA_DEMO=1` | Не тратит запросы к модели |
| Строгий аудит | `LORIA_AI_AUDIT=1` | Вторая модель проверяет каждый ход |

Лимиты (все задаются в `.env`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `LORIA_DAILY_REQUESTS` | 200 | Запросов к модели на игру в сутки |
| `LORIA_MAX_CREATES_PER_HOUR` | 40 | Новых историй в час с одного адреса (0 — без лимита) |
| `LORIA_MIN_TURN_GAP_MS` | 700 | Минимальная пауза между ходами одной игры |
| `LORIA_BOT_COOLDOWN_MS` | 1500 | Пауза между сообщениями бота |

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/health` | Состояние сервера и модели |
| `GET` | `/api/content` | Миры, архетипы, черты, бремени, сложности |
| `GET` | `/api/games` | Список историй |
| `POST` | `/api/games` | Создать игру и открывающую сцену |
| `GET` | `/api/games/:id` | Полное состояние |
| `POST` | `/api/games/:id/turn` | Ход; `{"action": "...", "boost": true}` — с рывком; SSE через `Accept: text/event-stream` |
| `POST` | `/api/games/:id/rest` | Передышка: энергия → здоровье, восстановление рывка |
| `POST` | `/api/games/:id/fork` | Ветка истории после смерти |
| `POST` | `/api/games/:id/rewind` | Отмена последнего хода (до 2 снимков) |
| `GET` | `/api/games/:id/levels` | Уровень, опыт и доступные улучшения |
| `POST` | `/api/games/:id/levelup` | Применить улучшение |
| `GET` | `/api/games/:id/download` | Сохранение в JSON |
| `POST` | `/api/import` | Импорт сохранения как новой истории |
| `POST` | `/api/games/:id/audit` | Проверить последний ход аудитором |
| `GET` | `/api/games/:id/export` | Хроника в Markdown |
| `DELETE` | `/api/games/:id` | Удалить историю |

## Структура

```
server/
  engine.js    общий движок хода: бросок → модель → валидатор → память
  index.js     HTTP API и статика
  telegram.js  Telegram-бот на том же движке
  dice.js      кубики и сложности
  state.js     правила состояния, рывок, передышка, смерть
  memory.js    гибридная память мира
  prompts.js   системные промпты мастера
  auditor.js   локальный и модельный аудит
  demo.js      резервный рассказчик
public/        клиент без сборки: index.html, styles.css, app.js, art/
scripts/       doctor.js, selftest, integration и bot-test: диагностика и проверки
  launcher.js  настольный запуск: браузер, порты, распаковка статики из .exe
  build-exe.mjs сборка автономного Loria.exe (Node SEA)
release/       готовый Loria.exe (в Git не попадает)
data/          сохранённые игры и сессии бота (в Git не попадают)
Dockerfile     образ без зависимостей, healthcheck на /api/health
```

Зависимостей нет: только стандартная библиотека Node. Фронтенд — ванильный JS и CSS.

### Мелкие удобства

- На узких экранах здоровье, энергия и опыт показаны компактной полосой прямо в шапке сцены.
- Лист героя помнит, где ты уже был: последние места собраны в отдельный блок.
- `Esc` закрывает и лист героя, и любое всплывающее окно.

## Безопасность и ограничения

- Ключ OpenRouter живёт только на сервере. В браузер уходят лишь тексты сцен.
- Игры хранятся локально в `data/games/*.json`, без авторизации: это приложение для одного игрока
  или для локальной сети. Для публичного хостинга добавь аутентификацию и общий лимит запросов.
- Модель может ошибаться в деталях — поэтому цифры и смерть считает сервер, а не она.
- Контент: тёмные темы допустимы, но промпт прямо запрещает сексуализацию несовершеннолетних
  и реальные инструкции по изготовлению оружия или наркотиков.
