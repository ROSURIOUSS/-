# Лория — веб-RPG с суверенным ИИ-мастером

Текстовая ролевая игра в духе [@Loria_AI_bot](https://t.me/Loria_AI_bot), но как самостоятельное приложение:
мастер не поддакивает, кубик кидает сервер, а аудитор состояния не даёт нарисовать себе 500 золота.

![Миры Лории](public/art/world-ash.jpg)

## Что внутри

- **Четыре готовых мира** — тёмное фэнтези «Пепел Вельдгарда», киберпанк «Хром и слякоть»,
  космический хоррор «Тишина „Кассандры“» и нуар «Дождь над Порт-Анной» — плюс конструктор своего мира.
- **Суверенный Гейм-Мастер.** Промпт запрещает мастеру льстить, решать за игрока и отменять последствия.
  У мира есть тон, правила и собственная логика — модель обязана им следовать.
- **Серверные броски.** d20 / 2d6 / d100, сложность зависит от типа действия, а не от настроения модели.
  Модель получает готовый результат и обязана narrate его, а не придумывать исход.
- **Валидатор состояния.** Любые изменения HP, энергии, золота, инвентаря, флагов и квестов проходят
  через жёсткие лимиты. Попытка выдать себе богатство срезается и попадает в журнал аудитора.
- **Гибридная память мира.** Незыблемые факты (клятвы, имена, смерти) + лексический поиск с IDF
  по прошлым сценам и свежести. Всё локально, без внешних эмбеддингов.
- **Аудитор правил.** Локальные проверки на каждом ходу (смерть без причины, экономика, агентность)
  и опциональная вторая модель для строгой проверки по кнопке.
- **Смерть окончательна.** На «Хардкоре» — без права на ошибку. Хронику можно забрать в Markdown.
- **Резервный рассказчик.** Если ключа нет или модель недоступна, игра не встаёт: сцены пишет
  процедурный движок с теми же правилами.

## Быстрый старт

```bash
# нужен Node.js 18+
npm start
```

Открой [http://localhost:3000](http://localhost:3000) и начни историю.

Ключ OpenRouter кладётся в `.env`:

```env
OPENROUTER_API_KEY=sk-or-...
LORIA_MODEL=google/gemini-2.5-flash
```

Файл `.env` уже исключён из Git. Ключ никогда не отдаётся браузеру — все запросы к модели идут с сервера.

Проверить окружение:

```bash
npm run doctor
```

Если модель молчит, доктор скажет почему:

| Ответ | Что делать |
|---|---|
| `401` | ключ отклонён — создай новый на openrouter.ai/keys |
| `402` | на ключе нет кредитов — сервер сам попробует бесплатные варианты моделей |
| «нет связи» | проверь интернет или задай прокси в `OPENROUTER_BASE_URL` |
| `404` | модель переименована — сервер возьмёт другую из каталога OpenRouter |

Дополнительно: `LORIA_MODELS` — список запасных моделей через запятую, `LORIA_AI_AUDIT=1` — строгий аудит каждым ходом.

## Как это работает

```
Браузер
  │  выбор мира, лист героя, память мира
  ▼
Node-сервер (без зависимостей)
  ├─ dice.js      серверный бросок + исход (модель не может его изменить)
  ├─ prompts.js   жёсткий системный промпт: мир, герой, память, запрет поддакивать
  ├─ ai.js        OpenRouter: перебор моделей, повторы, таймауты, JSON
  ├─ state.js     валидатор: лимиты HP / энергии / золота / инвентаря / флагов
  ├─ memory.js    факты + поиск по прошлым сценам (IDF, сущности, свежесть)
  ├─ auditor.js   локальный аудит и опциональная проверка второй моделью
  └─ store.js     JSON-файлы в data/games, экспорт в Markdown
```

Ход устроен так:

1. Игрок выбирает вариант или пишет своё действие.
2. Сервер определяет характеристику и сложность, кидает кубик, фиксирует исход.
3. Модель получает мир, героя, память, результат броска и возвращает JSON: сцену, варианты,
   предложенные изменения, факты для памяти, NPC.
4. Валидатор применяет изменения в допустимых пределах и записывает каждое ограничение в журнал.
5. Факты и фрагменты сцены уходят в память. Следующий ход мастер уже помнит, о чём вы договорились.

### Что именно запрещено модели

| Соблазн | Что происходит |
|---|---|
| «У меня 500 золота» | Валидатор срезает до лимита мира за ход, попытка логируется |
| Вылечить героя «насовсем» | Максимум +4 HP за ход |
| Объявить смерть без нуля HP | Смерть отклоняется аудитором |
| Решить за игрока, что он чувствует | Локальный аудит помечает нарушение агентности |
| Выдать предмет, которого нет | Инвентарь ограничен 16 слотами, лишнее отбрасывается |
| Проигнорировать бросок | Бросок уже в промпте, исход проверяется по тексту |

## Режимы

| Режим | Как включить | Что делает |
|---|---|---|
| ИИ-мастер | ключ в `.env` | Полноценные сцены через OpenRouter |
| Резервный | ключа нет или модель упала | Процедурные сцены, игра продолжается |
| Принудительный резерв | `LORIA_DEMO=1` | Не тратит запросы к модели |
| Строгий аудит | `LORIA_AI_AUDIT=1` | Вторая модель проверяет каждый ход |

Дневной лимит запросов на игру — `LORIA_DAILY_REQUESTS` (по умолчанию 200) — защита от лишних трат.

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/health` | Состояние сервера и модели |
| `GET` | `/api/content` | Миры, архетипы, черты, бремени, сложности |
| `GET` | `/api/games` | Список историй |
| `POST` | `/api/games` | Создать игру и открывающую сцену |
| `GET` | `/api/games/:id` | Полное состояние |
| `POST` | `/api/games/:id/turn` | Ход (JSON или SSE с `Accept: text/event-stream`) |
| `POST` | `/api/games/:id/audit` | Проверить последний ход аудитором |
| `GET` | `/api/games/:id/export` | Хроника в Markdown |
| `DELETE` | `/api/games/:id` | Удалить историю |

## Структура

```
server/     движок: броски, промпты, память, валидатор, API
public/     клиент без сборки: index.html, styles.css, app.js, art/
scripts/    doctor.js — проверка ключа и моделей
data/       сохранённые игры (в Git не попадают)
```

Зависимостей нет: только стандартная библиотека Node. Фронтенд — ванильный JS и CSS.

## Безопасность и ограничения

- Ключ OpenRouter живёт только на сервере. В браузер уходят лишь тексты сцен.
- Игры хранятся локально в `data/games/*.json`, без авторизации: это приложение для одного игрока
  или для локальной сети. Для публичного хостинга добавь аутентификацию и общий лимит запросов.
- Модель может ошибаться в деталях — поэтому цифры и смерть считает сервер, а не она.
- Контент: тёмные темы допустимы, но промпт прямо запрещает сексуализацию несовершеннолетних
  и реальные инструкции по изготовлению оружия или наркотиков.
