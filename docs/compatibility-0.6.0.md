# Проверка Sandustry 0.6.0 / PC Game Pass

Проверено по предоставленным пользователем файлам. Игра здесь не запускалась.

## Подтверждено кодом

- `package.json`: версия 0.6.0, Electron-приложение.
- `main.js`, `getLocalModsPath`: при платформе, отличной от `steam`, возвращает `null`.
- `main.js`, `discoverNativeWorkshopMods`: при платформе, отличной от `steam`, возвращает пустой список, не запуская обнаружение модов.
- `preload.js`: есть мост `electron.localMods`, но он не отменяет ограничения основного процесса.
- `external-mod-worker-runtime.js`: скриптам модов передаётся объект `sandkit`.
- Модуль 16403 в `simulation-worker.js`: рабочий API содержит чтение типа элемента, создание/удаление/перемещение элементов, измерения мира и события. Есть также низкоуровневый `engine.state`.
- В предоставленном оглавлении архива нет модуля `workshop-mods`, который запрашивает Steam-загрузчик. Простого удаления проверки платформы недостаточно.

## Не подтверждено

- Возможность запуска изменённого архива: проверка целостности Electron/пакета не исследована.
- Рабочий путь загрузки стороннего кода в Game Pass.
- Безопасное изменение клеток при многопоточной симуляции.
- Формат состояния частиц для переноса температуры, скорости, длительности и прочих полей.
- Реальная навигация, отрисовка бота, интерфейс и запись инвентаря в сохранение.

## Принятое решение

Не менять платформу на Steam, не отключать проверки лицензии или вход Xbox, не предлагать пользователю неподтверждённый патч архива.

Сначала реализован отдельный контроллер цикла бота. Следующий технический этап — исследовать создание main-фасада Sandkit и загрузку worker entry; затем создать минимальный диагностический запуск без изменения мира. Лишь после проверки запуска подключать добычу на тестовом мире.

## Требования к адаптеру контроллера

- `take(resource)`: атомарно извлечь одну единицу выбранного ресурса; вернуть полную запись для восстановления или `null`. При исключении мир должен остаться неизменным.
- `moveTo(cell)`: двигать реального бота, вернуть `true` только после достижения точки.
- `put(cell, record)`: атомарно восстановить запись в доступной клетке; вернуть `false`, если место занято. При исключении мир должен остаться неизменным.
- Не пересоздавать частицу только по её типу: это теряет остальные свойства.
- Не использовать контроллер одновременно в нескольких simulation workers.
- До подключения автосохранения обеспечить согласованную запись/восстановление груза и идентификатора мира. `snapshot()` пока только копирует состояние, не сохраняет его в игру.

## Дополнительная проверка переноса

Внутренняя реализация `teleport` переносит существующий индекс элемента, а не создаёт новый. Это потенциально сохраняет свойства лучше, чем удаление и создание, однако требует свободной клетки назначения и не даёт готового «инвентаря вне сетки». Поэтому использовать её как вместительный инвентарь без дополнительной реализации нельзя.

Рабочий фасад отдельно предоставляет velocity, duration и data fields. Это подтверждает, что сохранение только типа ресурса недостаточно. Поддержка полного переноса пока НЕ реализована.

Статический аудит можно повторить:

```sh
node tools/audit-game.mjs <папка-распакованных-файлов>
```

Результат проверки пользовательской сборки: `game-audit-0.6.0.json`. Инструмент читает текст, вычисляет SHA-256, не выполняет код игры и не меняет файлы. Совпадение текстовых признаков не является проверкой работающего мода.

## Состояние контроллера

Добавлены JSON-совместимые снимки и `ResourceBot.restore`. Восстановление допускается только с совпадающим ID мира; бот после него остановлен. Самостоятельно загружать такой снимок в уже работающий мир нельзя: игра и инвентарь должны сохраняться/восстанавливаться как единое согласованное состояние, иначе возможен повторный перенос ресурсов. Это требование к будущей интеграции, не решённое текущим контроллером.
